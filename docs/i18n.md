# Internacionalización — YACHAY ÑAN 3D

La interfaz es bilingüe **español / quechua**. El sistema vive en `src/i18n/` y no usa i18next ni ningún traductor automático.

## Uso

```ts
const { t, language, setLanguage, validationRatio } = useTranslation('home');

t('title');
t('phase', { count: 4 }); // interpola {{count}}
```

- Las claves salen de los JSON de `src/i18n/es`. TypeScript no deja escribir `t('clve')`.
- `setLanguage` guarda el idioma en las preferencias de accesibilidad y actualiza `<html lang>`.
- `validationRatio` es el porcentaje de cadenas no vacías del idioma activo (0 en quechua mientras el catálogo esté vacío).

## Por qué no hay traducción automática

Una cadena inventada en quechua no es un “borrador útil”: es un error que un niño o una docente pueden tomar por bueno. El proyecto enseña letras y palabras; no puede permitirse quechua de máquina.

Por eso `src/i18n/qu/` replica **las mismas claves** que el castellano, pero con valor `""`. Cadena vacía = fallback honesto al español y aviso en consola en desarrollo. Una traducción provisional de IA o de Google Translate quedaría prohibida aunque se etiquetara “por revisar”.

## Variante (Pendiente de declaración)

`src/i18n/qu/_meta.json` tiene `"variant": "POR DEFINIR"` y `"status": "pending_validation"`.

Hay que declarar la variante **antes** de llenar una sola cadena. En Pasco no es un detalle académico: el quechua que se habla en la región (rama Quechua I, a menudo agrupada como Yaru / Quechua Central) no es el mismo que el Quechua sureño (Cusco–Collao, Quechua II) que aparece en diccionarios y teclados genéricos. Elegir la forma de Cusco o Ayacucho para un aula de Pasco obliga a los estudiantes a leer una lengua “oficial” que no es la de su casa.

La elección la hacen hablantes de la zona y, si hace falta, la Dirección de Lenguas Indígenas del MINEDU. No la hace el código ni un modelo de lenguaje.

Mientras `status !== "validated"`, el selector muestra **Quechua (en validación)**, un `StatusBadge` de pendiente, y un aviso al activarlo. El texto visible sigue siendo castellano.

## Procedimiento de validación

1. Acordar y documentar la variante en `_meta.json` y en este archivo.
2. Traducir (persona hablante nativa de esa variante). No usar traductor automático.
3. Revisar con un segundo hablante o con la Dirección de Lenguas Indígenas del MINEDU.
4. Registrar en `_meta.json`:
   - `validatedBy`: nombre y rol (hablante nativo o institución)
   - `validatedAt`: fecha ISO
   - `status`: `"validated"`
5. Solo entonces desaparece el aviso del selector.

Hasta ese momento, `validatedBy` y `validatedAt` son `null`.
